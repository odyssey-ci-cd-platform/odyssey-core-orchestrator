# Changelog

Notable changes to odyssey-core-orchestrator. Latest changes go at the top, under `[Unreleased]`, until a version is tagged.

## [Unreleased]

### Added
- `internal/orchestrator` (gh-11): the pure segmentation slice — decodes a contract run-request envelope into the orchestrator's own consumer-side type (unknown fields ignored per additive evolution, no composer import), re-validates the envelope and the attached config at the trust boundary (shared rule set via the new `pipeline.Config.Validate`, so both boundaries reject the same pipelines with no TOML parser downstream), and turns a validated request plus a run id into contract-shaped job assignments: one per job, declared stage order, job names sorted within a stage (AUD-008), attempt 1, source carried through, job spec mirroring the resolved config, never outcomes. `Segment` documents the pipeline.started-before-any-assignment invariant at the segmentation site. No queue loop yet — that is the next work item.
- Process scaffolding: README with the architecture diagram and vocabulary, AGENTS.md conventions, RUNBOOK, docs-check gate, CI and issue/PR automation workflows, ship/merge scripts.
- ADR 0001: cluster orchestration — job-grain distribution, stateful stage state machine, feedback edge, failure modes, restart story.
- Dispatcher contract draft: streams, run request, job assignment, event emission responsibilities, delivery semantics.
- `internal/pipeline` (gh-5): parses and validates `.odyssey/pipeline.toml` into the contract's resolved configuration — TOML in, wire-shaped JSON out, `timeout` mapped to `timeout_ms`; every contract validation rule enforced and table-tested, all violations reported in one joined error, unknown keys rejected (parity with the dispatcher's config loader).
- The Go gate (gh-5): `go vet` / `go test ./...` / `go mod tidy -diff` / gofmt in `make check` and CI; RUNBOOK records the baseline.
- `internal/composer` (gh-7): the run request type with the contract's wire shape, envelope validation (origin enum, owner/repo slug, full 40-hex sha, non-empty trigger id and pipeline name — all violations in one error), and a publisher that writes single-envelope stream entries to `odyssey:pipeline-requests` with approximate MAXLEN trimming at the contract's default (10,000). Publish refuses invalid requests — the door holds at the wire.

### Changed
- Scoped the README to this repo: the architecture diagram keeps only composer and orchestrator inside the repo boundary, with triggers, the dispatcher repo, the event bus, and downstream consumers as boundary nodes, and the reading notes restate dispatcher-side mechanics as boundary references. Cross-references now name `odyssey-ci-cd-platform/dispatcher` (the current location of the repo formerly named `odyssey-core-agent`).
- Recorded the branch-protection setup in RUNBOOK: protection on `main` applied at repository creation (required `check` status, admins enforced, no required approvals).
- Untracked `gates.json` and ignored it: it is machine-local harness configuration (its `allowPaths` carries home-directory paths), not repo content. It remains in early history from the bootstrap commit; removal from published history was not attempted.
- Dispatcher contract frozen by the field-by-field pass (gh-3): every run-request and assignment field pinned with type, semantics, and units; the resolved pipeline configuration schema added (composer fetches and attaches — ADR 0001's open question settled); `setup` added to the job spec so setup commands survive the boundary (a setup failure is job-level `errored`, mirroring the dispatcher's `SetupErr`); step timeouts pinned as `timeout_ms` with `0` = no timeout; dispatcher-side validation enumerated to match `internal/config`'s `Validate`; per-event payload fields pinned from the dispatcher's emission code; dead-letter stream `odyssey:jobs-dead` named; delivery parameters fixed as v1 defaults (30s renewal, 5m idle threshold, attempt limit 3, queue MAXLENs).
- Made the orchestrator origin-blind and the composer a separate service (gh-9): `origin` removed from the run request as a named contract revision (intake provenance is the composer service's concern; the orchestrator never sees which surface produced a run), `internal/composer` trimmed to the origin-free shape with the wire test asserting origin's absence, and README/AGENTS now describe an orchestrator-only repo. The composer repo is planned; `internal/composer` is its seed and migrates at that repo's bootstrap; services consolidate into a monorepo later.
